# 定点本地推送配置

本地默认配置位于 `app/src/main/res/raw/local_push_default.json`，目前共 46 个场景。新增的 7 个场景已经写入 `scenes`，并同时进入 Firebase Remote Config 参数 `local_push_config_v1` 的 organic、paid 默认分段。远程 JSON 可以覆盖每个场景的时间、开关、频控和路由。

| 场景 key | 功能 | 默认本地时间 | 点击路由 |
| --- | --- | --- | --- |
| `scheduled_cache_scan` | 缓存扫描 | 11:30 | `cache_clean` |
| `scheduled_photo_compress` | 照片压缩 | 12:30 | `photo_compress` |
| `scheduled_video_compress` | 视频压缩 | 13:30 | `video_compress` |
| `scheduled_image_enhance` | 图片增强 | 14:30 | `image_enhancer` |
| `scheduled_contacts_manage` | 联系人管理 | 15:30 | `contacts_cleanup` |
| `scheduled_calendar_manage` | 日历管理 | 16:30 | `clean_calendar` |
| `scheduled_speed_test` | 网速测试 | 17:30 | `speed_test` |

修改时间时，在 organic 和 paid 对应场景的 `times` 数组内填写 `HH:mm`，例如 `"times": ["11:30"]`。支持每场景最多 8 个时间；时间按设备当地时区解释。修改远程配置后，应用重新排程。将场景 `enabled` 设为 `false` 可停发。旧远程快照若缺少这 7 个场景，应用会从本地默认配置补齐；已有的远程场景配置优先。

7 个场景默认属于 `normal_ntf`，各自每日最多 1 条、冷却 24 小时，并继续受全局和桶频控、通知权限以及前台跳过规则约束。因此到了设定时间也不保证一定展示。系统限制精确闹钟时会使用非精确调度；恢复任务只补发最近两小时内未成功提交的时段。

通知文案位于各语言目录的 `scheduled_new_push_strings.xml`，每个场景按现有轮换计数选择文案。`{size}`、`{apps}`、`{photos}`、`{saving}`、`{contacts}`、`{days}` 使用现有随机展示数值，不代表实时扫描结果。新增文案覆盖 21 条变体和全部 29 个语言资源目录；新增语言时需保持占位符名称不变。
